# DRAM 缺陷诊断竞赛项目方案：可靠长尾多标签识别

> 状态：当前实施方案
>
> 主协议：`dram-ml-v2`
>
> 任务类型：7 类可共存缺陷属性识别
>
> 优先目标：模型训练、可靠评估与竞赛预测；现有前端 UI 保持兼容

## 1. 项目背景与重构结论

项目使用自建标注工具完成重新标注，将任务定义为一张图可同时包含多个缺陷属性的多标签分类。

新版项目以可靠长尾多标签学习为核心：

- 使用冻结的 `label_v2.json` 作为人工标注源，任何修改都必须改变数据指纹并提升实验版本。
- 模型统一输出7个独立缺陷概率，允许一张图同时检出多个缺陷。
- 重点解决类别极不均衡、缺陷共现、阈值不稳定和测试泄漏问题。
- 主结论仅针对样本较充分的核心标签 `2/3/4/5`。
- 稀有标签 `1/7/8` 继续训练和输出，但作为少样本探索性结果单独报告。
- 通过普通 BCE、长尾加权 BCE、共现图残差模型的固定对照证明创新收益；复杂模型无稳定收益时自动回退。

## 3. `dram-ml-v2` 数据协议

### 3.1 协议内容

协议配置位于 `configs/protocols/dram_ml_v2.yaml`，冻结以下信息：

- `protocol_version: dram-ml-v2`；
- 类型清单 `[1,2,3,4,5,7,8]`；
- 核心标签 `[2,3,4,5]`；
- 稀有标签 `[1,7,8]`；
- 重点共现组合 `2+4`、`3+4`、`4+5`；
- 测试留出比例10%；
- 5折交叉验证；
- 划分随机种子42；
- 标注文件、数据集和 manifest 的 SHA-256 指纹。

协议版本、类别映射或 manifest 指纹不一致时，checkpoint 必须拒绝评估、集成和部署。

### 3.2 迭代多标签分层划分

不再使用简单图片随机划分。新版采用迭代多标签分层，同时平衡单标签支持度和重点共现组合：

- 锁定测试集：115 张，只允许最终评估一次。
- Development：1033 张，用于5折训练、验证和 OOF 阈值校准。
- 每折约80% development 训练、20%验证。
- 每张 development 图像恰好作为一次验证样本。
- 任何折的训练集、验证集和锁定测试集不得重叠。

预期测试集支持度为：标签1为2张、2为68张、3为16张、4为55张、5为9张、7为1张、8为2张。由于标签1/7/8的测试支持度仍很小，其结果不得用于宣称模型对这些标签已经具备稳定泛化能力。

### 3.3 数据审计

生成 manifest 前必须完成：

- 标注 CSV 与图片清单一致性检查；
- 图片存在性、可解码性和低质量检查；
- 文件哈希重复检查；
- 标签合法性、支持度、组合频率和共现矩阵统计；
- development/test 及各交叉验证折的标签覆盖检查；
- 跨 split 重复和数据泄漏检查；
- `label_v2.json`、数据标签映射和 manifest 指纹冻结。

## 4. 模型方案

### 4.1 通用训练设置

- Backbone：ImageNet 预训练 ResNet18。
- 输入：480×320 等比例 letterbox，灰度复制为三通道。
- 归一化：只使用当前训练折计算的 `dataset_gray` mean/std。
- 增强：轻度旋转、亮度、对比度和轻微模糊；不使用会破坏小缺陷的强裁剪或擦除。
- 冻结策略：前5个 epoch 冻结编码器，之后解冻微调。
- 学习率：编码器 `1e-4`、分类头 `3e-4`，AdamW 配合 cosine 衰减。
- 最大训练60个 epoch，patience 12，按核心标签 Macro-F1 保存最佳 checkpoint。
- 正式训练固定 seed 42；最终使用5折模型进行概率均值集成。

### 4.2 候选 A：普通 BCE 基线

模型输出7维 logits，使用标准 `BCEWithLogitsLoss`。该模型用于证明重新标注和正确多标签建模本身带来的收益，不引入类别权重或标签关系。

### 4.3 候选 B：长尾加权 BCE

每个训练折只根据本折训练样本计算正样本权重：

```text
pos_weight[c] = clamp(sqrt(N_negative[c] / N_positive[c]), 1, 5)
```

平方根缩放降低长尾标签的漏检风险，上限5避免标签1/7/8因样本过少主导梯度。验证集、OOF预测和测试集不得参与权重计算。

### 4.4 候选 C：共现关系约束的长尾多标签模型

这是项目的主要创新模型：

1. ResNet18 编码图像并生成7个原始 logits。
2. 仅使用当前训练折统计标签共现矩阵。
3. 只保留训练支持数不少于5的非对角关系。
4. 使用共现余弦强度构建归一化标签图。
5. 图消息以可学习强度作为残差加入原始 logits。

```text
raw_logits = classifier(image_embedding)
message = tanh(raw_logits) @ label_graph
logits = raw_logits + sigmoid(alpha) * message
loss = weighted_BCE(logits, labels)
```

`alpha` 初始有效值为0.1，使模型首先依赖图像证据，再学习是否需要共现修正。标签图必须随 checkpoint 保存，推理时不得根据测试数据重建。

### 4.5 模型保留和回退规则

三种候选按照 BCE、加权 BCE、共现图模型的固定顺序训练，使用完全相同的数据折、增强、backbone和训练预算。

共现图模型只有同时满足以下条件才被保留：

- 核心标签 OOF Macro-F1 不低于加权 BCE；
- 核心 Macro-F1 或三组共现组合平均 F1 至少提升0.005。

否则最终模型自动回退至加权 BCE。普通 BCE 只作为基础对照，不参与最终回退优先级。

## 5. OOF 阈值校准与集成

### 5.1 每标签阈值

固定0.5阈值仅用于训练过程观察，不作为最终判定阈值。所有 development 样本获得一次 OOF 概率后，对每个标签独立在 `[0.05,0.95]` 上以0.01步长搜索 F1 最优阈值。

- 核心标签使用 OOF 最优阈值。
- 稀有标签执行500次正负样本分层 bootstrap。
- 稀有标签取 bootstrap 阈值中位数，并按20个先验样本向0.5收缩。
- 保存原始阈值、中位数、5%/95%分位数、最终阈值和正样本支持度。
- 测试集和竞赛待预测数据不得参与阈值选择。

### 5.2 最终集成

- 使用同一候选的5个折模型。
- 对每张图分别计算5组 sigmoid 概率，再做算术平均。
- 平均概率与各标签校准阈值比较，得到最终多标签结果。
- 概率距离任一阈值不超过0.1时标记 `low_confidence=true`，供演示系统提示复核。

## 6. 评估方案

### 6.1 主指标

主指标为核心标签 `2/3/4/5` 的 Macro-F1。它避免高频标签2和4掩盖标签3和5的真实表现，同时不会让极少样本标签决定整体结论。

### 6.2 辅助指标

- 全7标签 Macro-F1；
- Micro-F1；
- 样本级 F1；
- mAP 和逐标签 PR-AUC；
- 每标签 Precision、Recall、F1、AUC和支持度；
- Exact Match 与 Hamming Loss；
- 5折核心 Macro-F1 均值、标准差和最低折结果。

### 6.3 共现组合指标

分别报告 `2+4`、`3+4`、`4+5` 的 Precision、Recall、F1和支持度。创新模型必须证明其改善来自正确识别共现缺陷，而不是仅改变总体阈值。

### 6.4 可靠性报告

- 对核心 Macro-F1进行按完整标签组合分层的2000次 bootstrap，报告95%置信区间。
- 报告各标签阈值的 bootstrap 区间。
- 标签1/7/8单独列出支持度与置信区间，明确标为探索性结果。
- 保存逐标签 PR 曲线数据、典型正确案例和错误最多案例。
- 不使用单次最高分代替折间均值与波动。

## 7. 测试集锁定规则

1. 先完成三组候选的全部 OOF 预测和阈值校准。
2. 按预设规则自动选择共现图模型或回退至加权 BCE。
3. 生成 `model_selection.json`，冻结协议指纹、模型类型、5个 checkpoint 哈希、OOF报告哈希、阈值和模型版本。
4. 评估程序只接受选择清单指定的模型。
5. `test_report.json` 与 `test_predictions.json` 已存在时拒绝覆盖。
6. 正式测试集只评估一次，不得根据测试结果修改阈值、损失、图结构或模型选择规则。
7. 若最终测试失败，该测试集视为已经消费；后续改进只能报告“已见测试集”结果，新的无偏验收需要新增或重新锁定未查看数据。

```json
    "4": 0.82,

    "7": 0.03,
    "8": 0.01
  },
  "predicted_labels": [2, 4],
  "thresholds": {
    "1": 0.42,
    "2": 0.51,
    "3": 0.37,
    "4": 0.48,
    "5": 0.33,
    "7": 0.46,
    "8": 0.44
  },
  "low_confidence": false,
  "model_version": "dram-ml-v2-graph_bce-ensemble"

```

竞赛提交 CSV 至少包含：

- `image_name`；
- `predicted_labels`；
- `prob_1` 至 `prob_8` 中实际使用的7个标签概率列；
- `pred_1` 至 `pred_8` 中实际使用的7个二值列；
- `low_confidence`；
- `model_version`。

前端 UI 沿用现有设计，通过部署清单读取5折 checkpoint 和每标签阈值。前端只展示概率、预测类型、低置信状态和相似案例，不参与模型选择或阈值调整。

## 9. 实验执行顺序

1. 将 `label_v2.json` 转换为多标签 CSV。
2. 使用 `dram_ml_v2.yaml` 执行数据审计并生成冻结 manifest。
3. 运行协议测试，确认1148张图像只覆盖一次且5折无泄漏。
4. 对 BCE 配置执行1 epoch、单折 smoke test。
5. 对加权 BCE 和共现图模型执行相同 smoke test。
6. 分别完成三个候选的5折正式训练。
7. 汇总 OOF 概率，生成每标签阈值、完整指标和置信区间。
8. 按固定规则生成模型选择锁定清单。
9. 在锁定测试集上执行唯一一次正式评估。
10. 使用选定的5折模型生成竞赛 CSV/JSON。
11. 将最终 checkpoint、阈值和模型版本接入现有演示前端。

## 11. 验收标准

### 11.1 数据与协议

- 有效图像严格为1148张，排除项及原因可追溯。
- 测试集115张、development 1033张。
- 5个验证折恰好覆盖全部 development 图像一次。
- 每折均包含7个标签的正样本，且重点组合尽量按比例分布。
- 没有重复图片、跨折泄漏或指纹不匹配。

### 11.2 训练与模型

- checkpoint 保存类别映射、协议与 manifest 指纹、fold、seed、归一化统计、正样本权重和标签图。
- BCE、加权 BCE、共现图模型使用一致训练预算。
- 最终模型选择完全由 OOF 结果和冻结规则决定。
- 共现图模型不满足收益条件时正确回退至加权 BCE。

### 11.3 评估与提交

- OOF 报告包含主指标、辅助指标、共现指标、折间波动和bootstrap置信区间。
- 标签1/7/8单独报告，不与核心标签混合形成可靠性结论。
- 正式测试报告不可覆盖，且只能由锁定模型生成。
- 竞赛预测使用5折 sigmoid 概率均值和冻结阈值。
- CSV和JSON的图像顺序、概率列、二值列及模型版本可审计。

## 12. 范围边界与后续方向

当前版本不把开放集未知拒识、工艺根因推断、自动增量学习或外部数据预训练作为竞赛主线。案例检索保留为演示和人工复核能力，但不参与主模型评分。

后续只有在新增或双人复核足够的标签1/7/8样本后，才将它们升级为正式核心指标。进一步研究可比较更强 backbone、自监督 SEM 表征和标签关系注意力，但必须新建实验版本，不得重复消费当前锁定测试集。
